# NX Insight

NX Insight [[~addon|افزونهٔ]] رسمی‌ای است که نشان می‌دهد کدام مسیرها از کاربرانتان
به [[~node|نودهایتان]] هنوز کار می‌کنند. هر مسیر یعنی یک شبکهٔ کلاینت (اپراتور، با
شمارهٔ ASN آن)، یک نود و یک [[~inbound]]. Insight نشان می‌دهد هر مسیر چطور کار
می‌کند، وقتی مسیری مسدود شود یا سانسورچی شروع به پروب کردن نودی کند هشدار می‌دهد،
و لینک‌هایی را که برای هر شبکه کار می‌کنند در اشتراک کاربران همان شبکه جلو می‌آورد.
این صفحه پیش‌نیازها، نصب، هر کدام از صفحه‌های Insight، و اینکه چه چیزی به کجا
فرستاده می‌شود را توضیح می‌دهد.

::: warning برآورد، نه اثبات
هر چه Insight نشان می‌دهد از روی شمارش به دست آمده است: شبکه‌ای که کم‌کار شده ممکن
است مسدود به نظر برسد، امتیاز پروب ممکن است با یک اسکن بالا برود، و یافتهٔ هوش مصنوعی
ممکن است به‌سادگی اشتباه باشد. پیش از جابه‌جا کردن کاربران یا عوض کردن یک آدرس، هر
یافته را با عددهای کنارش، و اگر می‌شود با یک کاربر واقعی روی همان شبکه، بسنجید.
:::

## پیش‌نیازها {#what-it-needs}

- پنل و نودها از **v0.1.3** به بعد. نودها می‌شمارند و پنل رله می‌کند. نودی با نسخهٔ
  قدیمی‌تر همچنان سرویس می‌دهد و فقط چیزی گزارش نمی‌کند، و Insight آن نود را
  «پشتیبانی نمی‌شود» نشان می‌دهد.
- شمارش روی همهٔ نودها خاموش است تا وقتی Insight آن را بخواند. اولین خواندن روشنش
  می‌کند؛ ده دقیقه پس از آخرین خواندن، یا حداکثر یک دقیقه پس از آن‌که توکن Insight
  حذف شود یا دسترسی‌اش را از دست بدهد، دوباره خاموش می‌شود. برای افزونه‌ای که نیست چیزی شمرده نمی‌شود.

## آنچه روی سرور شما می‌ماند {#what-stays-on-your-server}

نود هیچ‌وقت آدرس کلاینت را گزارش نمی‌کند، فقط شبکهٔ /24 (IPv4) یا /48 (IPv6) آن را، و برای آدرس 6to4 شبکهٔ /40.
پنل این عددها را بدون ذخیره کردن رد می‌کند. Insight همان لحظه که هر کدام را می‌خواند
آن را به اپراتور و منطقه تبدیل می‌کند و فقط اپراتور، کشور و منطقه را نگه می‌دارد.
نه پنل و نه Insight هیچ آدرس یا پیشوند شبکهٔ کلاینتی را جایی نمی‌نویسند.

اگر Insight را روی سرور خود پنل نصب کنید، این شبکه‌ها اصلاً از اینترنت عبور نمی‌کنند.

## نصب {#install}

در پنل: **افزونه‌ها ← مرور ← NX Insight ← نصب**. پنل سؤال‌هایش را می‌پرسد و آن را
روی سرور خودش یا سرور دیگری از راه SSH نصب می‌کند، یا دستوری برای اجرا به شما
می‌دهد. همهٔ راه‌های نصب در [[directory]] آمده است.

| سؤال | چه چیزی را تنظیم می‌کند |
| --- | --- |
| پورت | به‌طور پیش‌فرض `8099`. وقتی HTTPS روشن است، تنها پورت Insight. |
| دیتابیس | SQLite، یا PostgreSQL با رشتهٔ اتصالش. |
| اولین ادمین | یک نام و رمزی بین ۱۰ کاراکتر تا ۷۲ بایت. |
| مسیر ادمین | هر چه Insight سرو می‌کند زیر این مسیر است. تصادفی انتخاب می‌شود؛ خالی یعنی ریشه. |
| آدرس عمومی | جایی که Insight را باز می‌کنید: پروتکل، میزبان و پورت. |
| HTTPS | `panel`، `acme`، `acme-http`، `self-signed` یا `off`، مثل هر افزونهٔ دیگر ([[directory#https-for-the-addon]]). |
| پروکسی‌های معکوس مورد اعتماد | فقط پشت پروکسی معکوس: آدرس‌ها یا بازه‌های آن. خالی یعنی به هیچ `X-Forwarded-For` اعتماد نمی‌شود. |
| آدرس گوش دادن | خالی: همهٔ رابط‌ها. `127.0.0.1` فقط پشت پروکسی معکوسی روی همان سرور. |
| کشورهایی که منطقه‌هایشان جدا شود | به‌طور پیش‌فرض `IR,RU,CN`. کلاینت‌های این کشورها استان یا منطقه‌شان را هم می‌گیرند؛ بقیه فقط شبکه و کشور. |
| ربات، چت، پروکسی و آدرس Bot API تلگرام | جایی که هشدارها می‌روند. خالی: هشدارها فقط در Insight نگه داشته می‌شوند. با آدرس Bot API `https://tapi.bale.ai` هشدارها از راه ربات بله فرستاده می‌شوند. |
| زبان هشدارها | انگلیسی، فارسی، روسی یا چینی. |

دستی، روی یک سرور لینوکس با کاربر root:

```bash
sh install.sh --method docker --opt port=8099 --opt admin_password=… \
  --panel-url https://panel.example.com --claim-code …
```

`--method script` به‌جای Docker برنامه را زیر systemd اجرا می‌کند. اجرای دوبارهٔ همان
دستور آن را درجا به‌روز می‌کند؛ `--uninstall` آن را حذف می‌کند و `--purge`
داده‌هایش را هم پاک می‌کند.

وقتی Insight را تأیید می‌کنید، سه دسترسی می‌خواهد: خواندن آنچه نودها می‌شمارند (که
شمارش را روشن می‌کند)، چیدن لینک‌های همهٔ اشتراک‌ها، و خواندن آدرس نودها برای نشان
دادن اینکه هر نود کجا میزبانی می‌شود.

### ورود {#sign-in}

با مسیر ادمین در آدرس عمومی وارد شوید. Insight ادمین‌های خودش را دارد، نه ادمین‌های
پنل را. ورود دومرحله‌ای را در **امنیت** روشن کنید. رمز فراموش‌شده روی سرور بازنشانی
می‌شود:

```bash
insight admin reset-password -user admin -pass …
```

## نمای کلی {#overview}

بالای صفحه می‌گوید Insight پنل را می‌خواند یا نه:

| وضعیت | یعنی |
| --- | --- |
| در انتظار | هنوز در هیچ پنلی ثبت نشده. |
| در حال خواندن | کار می‌کند؛ زمان آخرین خواندن کنارش آمده. |
| پشتیبانی نمی‌شود | پنل قدیمی‌تر از v0.1.3 است. اول پنل و بعد نودها را به‌روز کنید. |
| بدون دسترسی | توکن Insight دسترسی خواندن ندارد. دسترسی‌هایش را در **افزونه‌ها** دوباره تأیید کنید. |
| ناموفق | آخرین خواندن ناموفق بود؛ Insight هر دقیقه دوباره امتحان می‌کند. |

زیر آن:

- **شبکه‌های قطع.** وقتی همهٔ مسیرها به یک اپراتور هم‌زمان روی دو نود یا بیشتر از کار
  بیفتند، مسدود شدن نودهای شما نیست بلکه قطع خود آن شبکه است: قطع اینترنت، یا لیست
  سفیدی که فقط بعضی سایت‌ها را باز می‌گذارد. Insight یک بار همین را می‌گوید و
  پیشنهادی برای عوض کردن چیزی نمی‌دهد.
- **تانل‌های بدون لینک.** کاربر به نود رلهٔ یک تانل وصل می‌شود و از نود مبدأ آن بیرون
  می‌رود؛ وقتی لینک بین این دو قطع شود، به نظر می‌رسد همهٔ شبکه‌ها روی رله هم‌زمان از کار
  افتاده‌اند. Insight هر دقیقه وضعیت هر تانل را از پنل می‌پرسد و تا وقتی تانلی لینک ندارد
  یک بار همین را می‌گوید — نه هشداری برای تک‌تک مسیرهای رله، و نه پیشنهادی برای تغییر
  چیزی روی رله.
- **مسیرهای مسدود**، هر کدام با مسیرهایی که برای همان شبکه هنوز کار می‌کنند.
- **ماتریس**: شبکه‌های کلاینت (یا منطقه‌ها) در کنار، نودها و inboundها در بالا، برای
  یک ساعت، شش ساعت، یک روز یا یک هفتهٔ گذشته. هر خانه سهم اتصال‌های آن شبکه است که
  رد شده‌اند. نشانگر را روی خانه ببرید تا عددها را ببینید: اتصال‌ها، احراز هویت‌شده‌ها،
  handshakeهای ناموفق، جلسه‌هایی که در چند ثانیه قطع شده‌اند، زمان رفت‌وبرگشت.
  خانهٔ یک اندپوینت WireGuard به‌جای آن handshakeهای موفق را نشان می‌دهد: WireGuard به
  handshake ناموفق جواب نمی‌دهد، پس شکست دیده نمی‌شود.

## نودها {#nodes}

شبکه‌ای که هر نود رویش میزبانی می‌شود، از روی آدرسش. جایی که پایگاه دادهٔ شبکه‌ها
نودی را اشتباه جا داده (بازه‌های یک ارائه‌دهنده، آدرسی پشت فرانت)، همین‌جا اصلاحش
کنید؛ این اصلاح پس از به‌روزرسانی‌های بعدی پایگاه داده هم می‌ماند.

کنار آن: آنچه نود سرویس می‌دهد — هر inbound و اندپوینت، با پروتکل، transport، امنیت
و اینکه domain front به آن می‌رسد یا نه — و [[use/tunnels|تانل‌هایی]] که نود رله یا
مبدأ آن‌هاست: لینک دارند یا نه، و در یک روز گذشته تعداد تلاش‌های اتصال، لینک‌های
برقرار، شکست‌ها و لینک‌هایی که بلافاصله پس از برقراری افتادند. خواندن تانل‌ها مجوز
`tunnels:read` را لازم دارد که Insight هنگام نصب درخواست می‌کند.

## پروب {#probing}

سانسورچی پیش از مسدود کردن یک سرور اغلب آن را آزمایش می‌کند: handshakeی را که از
یک کلاینت واقعی دیده دوباره می‌فرستد، یا درست بعد از وصل شدن یک کاربر واقعی پورت را
امتحان می‌کند. نودها این نشانه‌ها را می‌شمارند و هیچ واکنشی به آن‌ها نشان نمی‌دهند،
پس پروب‌کننده از این شمارش چیزی نمی‌فهمد.

هر نود و inbound برای شش ساعت گذشته امتیازی از ۰ تا ۱۰۰ می‌گیرد. هر handshake
تکراری ۲۰ امتیاز می‌دهد، تا سقف ۸۰؛ کلاینت واقعی هیچ‌وقت یک handshake را دو بار
نمی‌فرستد. موجی از handshakeهای ناموفق درست پس از جلسه‌های کاربران واقعی ۲۰ امتیاز
می‌دهد. در ۴۰ هشداری فرستاده می‌شود، همراه با کاری که باید کرد: پیش از رسیدن
مسدودسازی، پورت یا SNI آن inbound را عوض کنید (در REALITY سایت مقصد را هم)، یا به
نود آدرس دیگری بدهید. ستون **بعدش مسدود شد؟** می‌گوید آیا تا ۴۸ ساعت پس از هشدار
مسیری روی آن inbound مختل شد.

شمار SNIهای ناشناس روی یک [[protocols/ingress|ingress]] و بسته‌های QUIC نامعتبر روی
بازهٔ پورت Hysteria2 کنار امتیاز نشان داده می‌شوند ولی به آن اضافه نمی‌شوند: این‌ها
اسکنرند، نه پروبِ همین نقطهٔ اتصال.

## هشدارها {#alerts}

هر تغییر، تازه‌ترین اول: مسیری مختل شد یا برگشت، شبکه‌ای قطع شد یا برگشت، نقطهٔ
اتصالی زیر پروب رفت، تانلی قطع شد یا برگشت. هر مسیر با حالت عادی خودش در همان ساعتِ هفته سنجیده می‌شود که از
تاریخچه‌اش یاد گرفته می‌شود؛ مسیر پیش از آنکه بشود دربارهٔ آن قضاوت کرد به چند ساعت
ترافیک نیاز دارد، و پیش از هشدار به دو بررسی بد با فاصلهٔ پنج دقیقه. اگر در نصب ربات
تلگرام یا بله تعیین کرده باشید، هر هشدار به زبان نصب آن‌جا هم فرستاده می‌شود.

## اشتراک‌ها، بهترین لینک اول {#subscriptions-best-link-first}

برای هر اپراتوری که روی دو نود یا بیشتر دیده می‌شود، Insight به پنل می‌گوید کدام نودها
و inboundها برایش بهتر کار می‌کنند، و پنل آن لینک‌ها را در [[~subscription|اشتراک‌هایی]]
که از همان شبکه گرفته می‌شوند جلو می‌آورد. چیزی حذف نمی‌شود: کاربر همچنان همهٔ
لینک‌ها را می‌گیرد، فقط به ترتیبی بهتر. این ترتیب با تغییر مسیرها به‌روز می‌شود و اگر
شش ساعت به‌روز نشود منقضی می‌شود، پس با حذف Insight همهٔ اشتراک‌ها به ترتیب خود پنل
برمی‌گردند. هنگام قطع یک شبکه، ترتیب آن شبکه همان‌طور که بود می‌ماند.

## تحلیل هوش مصنوعی {#ai-analysis}

اختیاری: مدل هوش مصنوعی خودتان روزی یک بار برای هر کشوری که تفکیک منطقه را برایش
انتخاب کرده‌اید، و دوباره پس از هر
هشدار در آن کشور، مسیرهایتان را می‌خواند و می‌گوید چه می‌بیند: پروتکلی که برای یک
اپراتور مسدود است، آدرس نودی که در فهرست مسدودها رفته، کاربران را به کجا ببرید، چه
چیزی را عوض کنید. آن را در صفحهٔ **تحلیل هوش مصنوعی** تنظیم کنید:

| فیلد | |
| --- | --- |
| آدرس API | هر API سازگار با OpenAI: `https://api.openai.com/v1`، OpenRouter، یا Ollama روی سرور خودتان در `http://127.0.0.1:11434/v1`. |
| مدل | مدل کوچک محلی بد می‌خواند؛ مدلی با ۷B یا بیشتر، یا یک مدل آنلاین را ترجیح دهید. |
| کلید API | در دیتابیس Insight نگه داشته می‌شود و دیگر نشان داده نمی‌شود. مدل محلی کلید نمی‌خواهد. با تغییر پروتکل، میزبان یا پورت آدرس API، یا پروکسی، کلید پاک می‌شود و باید دوباره واردش کنید. |
| پروکسی | برای سروری که مستقیم به ارائه‌دهنده دسترسی ندارد. |
| بودجهٔ روزانهٔ توکن | بیش از آن، تا روز بعد (UTC) چیزی فرستاده نمی‌شود. |

آنچه فرستاده می‌شود: برای هر اپراتور (شمارهٔ AS و نام ثبت‌شده‌اش)، شمارهٔ نود و تگ
inbound، شمارش‌ها و نسبت‌های ۲۴ ساعت گذشته؛ کشور و شرکت میزبان هر نود؛ امتیازهای
پروب و تعداد هشدارها؛ هر تانلی که به این نودها مربوط است، با نامش، شمارهٔ نود رله و
مبدأ و اینکه لینک دارد یا نه. هیچ‌وقت آدرس کلاینت یا نود و نام نود فرستاده نمی‌شود. تگ
inboundها، نام تانل‌ها و نام شرکتی که در صفحهٔ نودها نوشته‌اید همان‌طور که نوشته‌اید می‌روند، فقط
با حداکثر چهل حرف، رقم، فاصله، خط تیره و زیرخط (نقطه‌ها حذف می‌شوند)؛ پس آدرسی در آن‌ها نگذارید. چیزی به NX نمی‌رود. هر یافته با همان عددهایی که به مدل داده شده
سنجیده می‌شود و اگر عددها آن را تأیید نکنند کنار گذاشته می‌شود، پس مدلی که اشتباه
حدس بزند به‌جای چیزی نادرست، چیزی نشان نمی‌دهد.

## داده‌ها {#data}

داده‌های IP به ASN از [iptoasn.com](https://iptoasn.com). مکان‌یابی IP از
[DB-IP](https://db-ip.com) با مجوز
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). هر نصب هر دو را خودش
دانلود می‌کند: شبکه‌ها را روزانه، منطقه‌ها را ماهانه.

Insight عددهای ساعتی را هفت روز و عددهای روزانه را ۹۰ روز نگه می‌دارد.
