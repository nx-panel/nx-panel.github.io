# Обновление

[[~panel|Панель]] и [[~node|узлы]] выпускаются и обновляются отдельно.
**Сначала обновите панель, потом узлы.** Более новый узел может уже не
отвечать на запрос, на который рассчитывает старая панель, например снять
учётную запись с узла в момент её истечения.

## Панель с её собственной страницы {#the-panel-from-its-own-page}

Раз в день панель проверяет, нет ли нового выпуска, и показывает баннер, если
он есть. **Настройки → Обновление панели** показывает установленную версию,
новейший выпуск, способ установки этой панели и описание выпуска.

При установке скриптом **Обновить сейчас** выполняет всё обновление:

1. **Резервная копия** базы в ваш каталог резервных копий. Перед ней панель
   проверяет, что список контрольных сумм выпуска (`SHA256SUMS`) подписан NX.
2. **Загрузка** выпуска.
3. **Проверка**, что архив совпадает с этим подписанным списком, и пробный
   запуск, чтобы убедиться, что он стартует на этом сервере.
4. **Установка**, при которой старый бинарный файл сохраняется как
   `/opt/nx-panel/nx-panel.previous`.
5. **Перезапуск.** Вы остаётесь в системе, если в описании выпуска не сказано
   иное: после обновления до v0.1.2 на панели, открытой по HTTPS, все входят ещё
   раз, потому что изменился cookie входа. Панель недоступна несколько секунд, и страница сообщает,
   когда она вернулась.

Устанавливаются только выпуски, подписанные NX. Выпуск публикуется немного
раньше, чем подписывается; в этот промежуток страница показывает его как
доступный, а обновление останавливается с *not signed yet* ещё до резервной
копии и ничего в панели не меняет. Попробуйте позже.

Если новая сборка не поднимается, примерно за десять секунд автоматически
возвращается прежний бинарный файл, а страница показывает **Откат**.

::: warning База данных не откатывается
Изменения базы идут только вперёд. Если после обновления что-то не так, путь
назад — резервная копия из шага 1. Она восстанавливается только в ту версию,
которая её создала: сначала снова установите предыдущую версию
(`install.sh --version vX.Y.Z`), затем восстановите копию в **Настройки →
Резервная копия** (см. [[use/backup]]).
:::

::: danger Возврат к более старой версии
Начиная с выпуска, в котором появилась страница **Настройки → Адреса**
([[use/ingress]]), панель хранит свои порты, домены, пути и HTTPS в новом виде,
а старые настройки удаляются из базы. Более старая версия, запущенная на этой
базе, не находит ни одной из них: она поднимается на порту 2095, по обычному
HTTP, без домена и пути.

- **Сделайте резервную копию перед обновлением и сохраните её.** Обновление со
  страницы делает её на шаге 1; установщик копирует базу SQLite в
  `nx.db.bak`.
- **Не возвращайтесь**, устанавливая старую версию поверх новой.
- Если обновление с этой страницы не удалось и прежняя версия вернулась сама,
  происходит то же самое. Запустите обновление ещё раз, при необходимости с
  сервера, или восстановите копию, сделанную перед обновлением, командой
  `nx-panel restore FILE -keep-web-settings=false` и перезапустите панель.
:::

**Ежедневно проверять выпуски** выключает ежедневную проверку. Тогда панель
спрашивает только по нажатию **Проверить**, и кнопка по-прежнему работает.

Ежедневная проверка сначала обращается к nx-panel.org и передаёт четыре
вещи: версию панели, её архитектуру, контрольную сумму её собственного
исполняемого файла и есть ли у неё лицензия. Если nx-panel.org не отвечает,
панель спрашивает GitHub, уже без них.

### Что записывает nx-panel.org {#what-nx-panel-org-records}

Установка, обновление и проверка новой версии идут через nx-panel.org.
Каждый запрос записывает версию и платформу панели, контрольную сумму её
исполняемого файла, есть ли у неё лицензия, а также адрес, с которого он
пришёл, вместе со страной. Эти данные используются для статистики лицензий и
выпусков. Адреса удаляются через 12 месяцев; счётчики сохраняются. Выключение
проверки обновлений (**Ежедневно проверять выпуски** в
**Настройки → Обновление панели**) останавливает ежедневный запрос панели.

## Панель из командной строки {#the-panel-from-the-command-line}

Запустите установщик ещё раз. Он найдёт существующую установку и обновит её
на месте:

```bash
bash <(curl -fsSL https://nx-panel.org/install.sh)
```

Чтобы обновиться напрямую с GitHub, без nx-panel.org (см.
[[install-panel#straight-from-github]]):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/nx-panel/panel/main/install.sh) --github
```

Он останавливает службу, копирует базу SQLite в `nx.db.bak`, сохраняет
прежний бинарный файл, обновляет базу и запускает службу снова. Ваши
настройки и учётные записи администраторов не затрагиваются. С PostgreSQL
сначала сделайте дамп базы сами.

## Панель в Docker {#the-panel-in-docker}

Контейнер не может заменить собственный образ, и страница «Обновление панели»
об этом сообщает. В каталоге с файлом compose:

```bash
docker compose pull && docker compose up -d
```

## Узлы {#the-nodes}

Раздел **Узлы** на странице **Обновление панели** показывает новейший выпуск
узла и сколько узлов от него отстаёт.

- **Обновить все узлы** обновляет узлы по очереди по SSH. Узел, для которого у
  панели нет разрешённого SSH-ключа, пропускается.
- **Один узел:** откройте у него окно **Установка**, перейдите на
  **Автоматически (SSH)** и нажмите **Обновить**. Панель загружает новый
  бинарный файл (или скачивает новый образ) и перезапускает узел.
- **Вручную:** снова выполните команду установки узла на его сервере. Она
  найдёт существующую установку, сохранит её конфигурацию и сертификаты и
  заменит только бинарный файл.
- **Узел в Docker:** `docker compose pull && docker compose up -d`.

Обновление сохраняет сертификаты узла, поэтому панель по-прежнему его
узнаёт и заново регистрировать ничего не нужно.

Панель загружает на узлы ту копию бинарного файла, которую хранит у себя
(**Загружено на эту панель**). Когда эта копия старше новейшего выпуска узла,
**Скачать последний узел** обновляет её, а обновление узла до этого момента
берёт новейшую версию с GitHub.

## Во время обновления {#during-an-update}

Пока панель перезапускается, узел продолжает работать: обновление панели ни
у кого не обрывает соединение. Узел, который три минуты не может связаться
со своей панелью, перестаёт обслуживать, пока панель не вернётся, поэтому не
оставляйте панель выключенной надолго.
