# NX Insight

NX Insight — официальный [[~addon|аддон]], который показывает, какие пути от ваших
пользователей к вашим [[~node|узлам]] ещё работают. Путь — это одна сеть клиентов
(провайдер, по номеру ASN), один узел и один [[~inbound]]. Insight показывает, как
работает каждый путь, предупреждает, когда путь заблокирован или цензор начинает
зондировать узел, и ставит ссылки, которые работают для каждой сети, первыми в
подписках её пользователей. На этой странице — что нужно, установка, каждая страница
Insight и что куда отправляется.

::: warning Оценки, а не доказательства
Всё, что показывает Insight, выведено из подсчётов: затихшая сеть может
выглядеть заблокированной, оценка зондирования может вырасти от сканирования, а
вывод ИИ может быть просто ошибочным. Прежде чем переводить пользователей или
менять адрес, сверьте вывод с цифрами рядом и, если можно, с реальным
пользователем в этой сети.
:::

## Что нужно {#what-it-needs}

- Панель и узлы начиная с **v0.1.3**. Узлы считают, панель передаёт. Узел более
  старой версии продолжает работать и просто ничего не сообщает, а Insight
  показывает его как неподдерживаемый.
- Подсчёт на всех узлах выключен, пока Insight его не читает. Первое чтение
  включает его; он снова выключается через десять минут после последнего чтения
  или не позже чем через минуту после того, как токен Insight удалён или теряет право. Для аддона, которого
  нет, ничего не считается.

## Что остаётся на вашем сервере {#what-stays-on-your-server}

Узел никогда не сообщает адрес клиента — только его сеть /24 (IPv4) или /48
(IPv6), а для адреса 6to4 — /40. Панель передаёт эти числа, не сохраняя их. Insight в момент чтения
превращает каждое в провайдера и регион и хранит только провайдера, страну и
регион. Ни панель, ни Insight нигде не записывают адрес или префикс сети клиента.

Установите Insight на сервер самой панели — и эти сети вообще не пересекают
интернет.

## Установка {#install}

В панели: **Аддоны → Каталог → NX Insight → Установить**. Панель задаёт свои
вопросы и устанавливает его на свой сервер или на другой по SSH либо выдаёт
команду для запуска. Все способы установки — в [[directory]].

| Вопрос | Что задаёт |
| --- | --- |
| Порт | По умолчанию `8099`. С включённым HTTPS — единственный порт Insight. |
| База данных | SQLite или PostgreSQL со строкой подключения. |
| Первый администратор | Имя и пароль от 10 символов до 72 байт. |
| Путь админки | Всё, что отдаёт Insight, — под ним. Выбирается случайно; пусто — корень. |
| Публичный адрес | Где вы открываете Insight: схема, хост и порт. |
| HTTPS | `panel`, `acme`, `acme-http`, `self-signed` или `off`, как у любого аддона ([[directory#https-for-the-addon]]). |
| Доверенные обратные прокси | Только за обратным прокси: его адреса или диапазоны. Пусто — `X-Forwarded-For` не доверяется. |
| Адрес прослушивания | Пусто — все интерфейсы. `127.0.0.1` — только за обратным прокси на том же сервере. |
| Страны, где различать регионы | По умолчанию `IR,RU,CN`. Клиенты там получают ещё и область; клиенты в других странах — сеть и страну. |
| Бот, чат, прокси и адрес Bot API Telegram | Куда идут оповещения. Пусто — оповещения только хранятся в Insight. Адрес Bot API `https://tapi.bale.ai` отправляет их через бота Bale. |
| Язык оповещений | Английский, персидский, русский или китайский. |

Вручную, на сервере Linux от root:

```bash
sh install.sh --method docker --opt port=8099 --opt admin_password=… \
  --panel-url https://panel.example.com --claim-code …
```

`--method script` запускает программу под systemd вместо Docker. Повторный запуск
той же команды обновляет на месте; `--uninstall` удаляет, а `--purge` удаляет и
данные.

При одобрении Insight просит три права: читать то, что считают узлы (это включает
подсчёт), упорядочивать ссылки всех подписок и читать адреса узлов, чтобы показать,
где размещён каждый узел.

### Вход {#sign-in}

Войдите по публичному адресу с путём админки. У Insight свои администраторы, не
панели. Включите двухфакторный вход в разделе **Безопасность**. Забытый пароль
сбрасывается на сервере:

```bash
insight admin reset-password -user admin -pass …
```

## Обзор {#overview}

Вверху страницы — читает ли Insight панель:

| Состояние | Что значит |
| --- | --- |
| Ожидание | Ещё не зарегистрирован в панели. |
| Чтение | Работает; рядом — время последнего чтения. |
| Не поддерживается | Панель старше v0.1.3. Обновите её, затем узлы. |
| Нет права | Токену Insight не хватает права на чтение. Одобрите его права заново в разделе **Аддоны**. |
| Ошибка | Последнее чтение не удалось; Insight повторяет каждую минуту. |

Ниже:

- **Отрезанные сети.** Когда все пути к одному провайдеру одновременно не работают
  на двух узлах и более, заблокированы не ваши узлы — отрезана сама сеть:
  отключение или белый список, пропускающий лишь некоторые сайты. Insight говорит
  об этом один раз и ничего не предлагает менять.
- **Туннели без связи.** Пользователь подключается к узлу-ретранслятору туннеля и
  выходит через его выходной узел; когда связь между ними обрывается, кажется, что на
  ретрансляторе разом отказали все сети. Insight раз в минуту спрашивает панель о
  каждом туннеле и, пока у туннеля нет связи, говорит об этом один раз — без
  оповещения по каждому пути ретранслятора и без предложений что-то менять на нём.
- **Заблокированные пути** — каждый с путями, которые ещё работают для той же сети.
- **Матрица**: сети клиентов (или регионы) по вертикали, узлы и inbound по
  горизонтали, за последний час, шесть часов, сутки или неделю. Каждая ячейка — доля
  соединений этой сети, которые прошли. Наведите курсор, чтобы увидеть числа:
  соединения, аутентифицированные, неудачные рукопожатия, сессии, оборванные за
  секунды, время приёма-передачи.
  Ячейка точки WireGuard вместо этого показывает удачные рукопожатия: WireGuard не
  отвечает на неудачное рукопожатие, поэтому отказ не виден.

## Узлы {#nodes}

Сеть, в которой размещён каждый узел, по его адресу. Если база сетей размещает узел
неверно (диапазоны провайдера, адрес за фронтом), исправьте здесь; исправление
сохраняется при последующих обновлениях базы.

Рядом: что обслуживает узел — каждый inbound и точку подключения с протоколом,
транспортом, защитой и тем, доходит ли до него доменный фронт, — и
[[use/tunnels|туннели]], в которых он ретранслятор или выход: есть ли связь и за
последние сутки попытки связи, установленные связи, отказы и связи, оборвавшиеся сразу
после установки. Чтобы читать туннели, нужно право `tunnels:read`, которое Insight
запрашивает при установке.

## Зондирование {#probing}

Прежде чем заблокировать сервер, цензор часто проверяет его: повторно отправляет
рукопожатие, которое видел от настоящего клиента, или пробует порт сразу после
подключения настоящего пользователя. Узлы считают эти признаки и никак на них не
реагируют, поэтому зондирующий ничего не узнаёт из подсчёта.

Каждый узел и inbound получает оценку от 0 до 100 за последние шесть часов. Каждое
повторённое рукопожатие добавляет 20, до 80: настоящий клиент никогда не отправляет
одно рукопожатие дважды. Всплеск неудачных рукопожатий сразу после сессий настоящих
пользователей добавляет 20. При 40 отправляется оповещение с тем, что делать: до
блокировки смените порт или SNI этого inbound (для REALITY — и целевой сайт) или дайте
узлу другой адрес. Столбец **Заблокирован после?** показывает, деградировал ли путь
на этом inbound в течение 48 часов после оповещения.

Счётчики неизвестных SNI на [[protocols/ingress|ingress]] и посторонних пакетов QUIC
на диапазоне портов Hysteria2 показаны рядом с оценкой, но не входят в неё: это
сканеры, а не зондирование этой точки.

## Оповещения {#alerts}

Каждое изменение, новые сверху: путь деградировал или восстановлен, сеть отрезана
или вернулась, точку подключения зондируют, туннель упал или восстановлен. Каждый путь сравнивается с его
собственной нормой для этого часа недели, выученной по истории; пути нужно несколько
часов трафика, прежде чем его можно оценить, и две плохие проверки с интервалом в
пять минут, прежде чем придёт оповещение. Если при установке задан бот Telegram или
Bale, каждое оповещение отправляется и туда, на языке установки.

## Подписки: лучшая ссылка первой {#subscriptions-best-link-first}

Для каждого провайдера, замеченного на двух узлах и более, Insight сообщает панели,
какие узлы и inbound работают для него лучше, и панель ставит эти ссылки первыми в
[[~subscription|подписках]], загруженных из этой сети. Ничего не удаляется:
пользователь по-прежнему получает все ссылки, только в лучшем порядке. Порядок
обновляется при изменении путей и истекает через шесть часов без обновления, поэтому
после удаления Insight все подписки возвращаются к порядку самой панели. Пока сеть
отрезана, её порядок остаётся прежним.

## ИИ-анализ {#ai-analysis}

Необязательно: ваша собственная модель раз в день для каждой страны, в которой вы
выбрали различать регионы, а также
после оповещения там, читает ваши пути и говорит, что видит: протокол, заблокированный
для одного провайдера, адрес узла в списке, куда перевести пользователей, что сменить.
Настройте на странице **ИИ-анализ**:

| Поле | |
| --- | --- |
| Адрес API | Любой OpenAI-совместимый API: `https://api.openai.com/v1`, OpenRouter или Ollama на вашем сервере по адресу `http://127.0.0.1:11434/v1`. |
| Модель | Маленькая локальная модель читает плохо; лучше 7B и больше или облачная модель. |
| Ключ API | Хранится в базе Insight и больше не показывается. Локальной модели не нужен. При смене схемы, хоста или порта адреса API либо прокси ключ сбрасывается: введите его снова. |
| Прокси | Для сервера, который не достаёт до провайдера напрямую. |
| Дневной бюджет токенов | Сверх него ничего не отправляется до следующего дня (UTC). |

Что отправляется: по каждому провайдеру (номер AS и зарегистрированное имя), номеру
узла и тегу inbound — счётчики и доли за последние 24 часа; страна и провайдер
хостинга каждого узла; оценки зондирования и число оповещений; каждый туннель этих
узлов — по имени, с номерами узла-ретранслятора и выходных узлов и тем, есть ли у него
связь. Никогда — адрес
клиента или узла и имя узла. Теги inbound, имена туннелей и провайдер, которого вы ввели на странице
«Узлы», уходят как написаны, не длиннее сорока символов из букв, цифр, пробелов, дефисов и подчёркиваний (точки убираются), поэтому не пишите
в них адрес. В NX ничего не уходит. Каждая находка сверяется с теми
числами, которые получила модель, и отбрасывается, если они её не подтверждают, так
что ошибающаяся модель не показывает ничего, а не что-то неверное.

## Prometheus и Grafana {#prometheus-and-grafana}

Если при установке задать токен в вопросе **Токен для Prometheus**, Insight
отдаёт `/metrics` под путём админки для вашего Prometheus, а в репозитории
панели есть дашборд Grafana для него: доля успешных, сессии, отказы и ранние
обрывы по узлу и сети клиента, пути, деградировавшие сейчас, туннели без связи
и оценки зондирования. Настройка — в [[how/monitoring#nx-insight-paths]]. Как
и всё здесь, адресов клиентов в нём нет.

## Данные {#data}

Данные IP → ASN от [iptoasn.com](https://iptoasn.com). Геолокация IP от
[DB-IP](https://db-ip.com) по лицензии
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Каждая установка скачивает
их сама: сети — ежедневно, регионы — ежемесячно.

Insight хранит почасовые данные семь дней, а суточные — 90 дней.
