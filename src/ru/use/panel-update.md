# Обновление из панели

**Настройки → Обновление панели** сравнивает установленную версию с
последним выпуском, обновляет саму панель при стандартной установке и
поддерживает актуальными бинарные файлы узла, которые панель передаёт вашим
серверам. Открыть страницу может только главный администратор. Об обновлении
из командной строки и о порядке обновления см. [[start/update]].

## Проверка выпусков {#release-check}

Страница показывает:

- **Установлено** и **Последний выпуск** с отметкой **Доступно обновление**
  или **Актуальная версия** и ссылкой на **Описание выпуска**;
- **Способ установки**: служба systemd, контейнер или запуск вручную;
- **Последняя проверка** и кнопку **Проверить**, чтобы проверить ещё раз.

Панель проверяет выпуски раз в день и показывает баннер, когда выходит новый.
Ежедневная проверка сначала обращается к nx-panel.org и передаёт четыре
вещи: версию панели, её архитектуру, контрольную сумму её собственного
исполняемого файла и есть ли у неё лицензия. Если nx-panel.org не отвечает,
панель спрашивает GitHub, уже без них. Что записывает nx-panel.org, описано в
[[start/install-panel#what-nx-panel-org-records]]. Выключите проверку
переключателем **Ежедневно проверять выпуски** или из командной строки (см.
[[reference/cli]]). Тогда панель спрашивает только по нажатию **Проверить**,
и кнопка обновления по-прежнему работает.

## Обновление панели {#updating-the-panel}

При установке через systemd **Обновить сейчас** (или **Обновить до** *версия*)
выполняет всё обновление:

1. **Резервная копия**: копия базы данных в ваш каталог резервных копий. Перед
   ней панель проверяет, что список контрольных сумм выпуска (`SHA256SUMS`)
   подписан NX.
2. **Загрузка** выпуска.
3. **Проверка**, что архив совпадает с этим подписанным списком, и пробный
   запуск, чтобы убедиться, что он стартует на этой машине.
4. **Установка**: замена бинарного файла с сохранением предыдущего рядом.
5. **Перезапуск** на новой версии.

Вы остаётесь в системе, если в описании выпуска не сказано иное: после
обновления до v0.1.2 на панели, открытой по HTTPS, все входят ещё раз, потому что изменился cookie входа.
Панель недоступна несколько секунд, и страница сообщает, когда она вернулась.
Узлы продолжают работать во время перезапуска, поэтому пользователи ничего не
теряют.

### Только подписанные выпуски {#only-signed-releases}

Кнопка обновления устанавливает только выпуски, подписанные NX. Выпуск
публикуется немного раньше, чем подписывается: в этот промежуток страница
показывает его как доступный, а обновление останавливается с *not signed yet*
ещё до резервной копии и ничего в панели не меняет. Попробуйте позже. Выпуск с
подписью не от NX отклоняется в том же месте, а архив, не совпадающий с
подписанным списком, отклоняется до того, как что-либо будет установлено.

### Если новая версия не запускается {#if-the-new-version-does-not-start}

Если новая сборка не поднимается, панель сама возвращает предыдущий бинарный
файл примерно за десять секунд, и страница показывает **Откат**.

База данных **не** откатывается: обновления только продвигают её вперёд. Если
после обновления что-то не так, путь назад — копия, сделанная на первом шаге.
Страница называет её. Копия восстанавливается только в ту версию, которая её
создала: сначала снова установите предыдущую версию
(`install.sh --version vX.Y.Z`), затем восстановите её в **Настройки →
Резервная копия** (см. [[backup]]).

## Установки в Docker {#docker-installs}

Панель в контейнере не может заменить собственный образ, и страница прямо
сообщает об этом, не пытаясь обновиться. Обновите её из каталога вашего
compose-файла:

```bash
docker compose pull && docker compose up -d
```

## Выпуски узла {#node-releases}

Раздел **Узлы** на странице показывает **Последний релиз узла** и
**Отстающие узлы**.

Панель хранит копию бинарных файлов узла, которые загружает на ваши серверы
при установке или обновлении узла. **Скачать последний узел** загружает в эту
копию последний выпуск. **Загружено на эту панель** показывает, что там
лежит, и отмечает версию как **актуально** или **старее**. Если копия старее
последнего выпуска, при обновлении узла последний выпуск берётся напрямую с
GitHub.

**Обновить все узлы** обновляет по SSH каждый отстающий узел по очереди. Узел,
для которого у панели нет SSH-ключа, пропускается; обновите его из его
собственного диалога установки. См. [[nodes]].

::: tip
Обновляйте панель раньше узлов. Более новый узел в паре с более старой
панелью может пропустить запрос панели отключить аккаунт, у которого истёк
срок или закончился трафик, пока этот узел не обновит что-то другое.
:::
